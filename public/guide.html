Five rules that turn logs into telemetry

A silent bug is one that runs without throwing — wrong totals, skipped steps, stale branches. Exceptions can't see it. The only thing that can is a trace of what the code actually did. These are the rules that make a trace worth having.

1. Log the boundary, not the internals

Emit a line when a request enters and leaves a boundary: HTTP handler, queue consumer, external API call. What happens inside a loop is trivia; what crossed the edge is the record. In the lab, the naive lane logs every loop iteration — six orders produce a wall of text where nothing can be found. The disciplined lane emits three lines per order: entry, decision, exit.

2. Log the decision, not just the outcome

Record which branch fired and why: coupon.applied with the code, kind, and the discountCents it produced. Without the decision line, you re-derive intent by re-reading code — the same code that has the bug.

3. Log the failure — and the request — with context

An error line without a requestId is a corpse without a name. The ID joins every line a request emitted into one story, and the logged fields carry enough input to reproduce it. In the lab, the hunter joins lines by requestId and replays the arithmetic — that's the whole detection mechanism.

4. Never log secrets or PII

Logs replicate to vendors, indexes, and dashboards — a wider audience than your database. The naive lane prints the customer email and card fixture; the disciplined lane never touches them. Redact by allowlisting fields at the logger, not by promising to be careful.

5. Structured fields over free text

"done total 5310" can't be queried; {"event":"checkout.done","totalCents":5310} can be parsed, joined, recomputed, and alerted on. A log line you can't query isn't telemetry — it's a diary.

How the detection works

The hunter never runs an oracle next to the service. It joins the disciplined lane's lines by requestId: entry says shippingCents: 900, no freeship decision fired, yet exit charges shippingCents: 0. The trace contradicts itself — that's the silent bug, caught by arithmetic on logged fields. The other two modes can't be reconstructed at all: none emits nothing; naive emits text with no ID to join on and no fields to recompute.

Honest limits: the checker knows this service's fields. The rule that generalizes is "log enough structured context to replay what happened" — the specific assertions are demo-sized on purpose.
